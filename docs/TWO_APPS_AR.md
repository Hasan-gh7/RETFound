# تشغيل Eye AI وموقع RETFound بشكل مستقل

من PowerShell شغّل أمر المضيف المعتاد:

```powershell
& "$env:USERPROFILE\.conda\envs\ml-homework\python.exe" -B "C:/Users/jadgh/Desktop/Dr 4/Dr/RETFound/scripts/share_api.py"
```

أدخل مفتاح OpenRouter في نافذة الخادم فقط. بعد جاهزية الرابط الخارجي،
يبدأ التطبيقان ويفتح المتصفح رابطين:

- Eye AI: http://127.0.0.1:8001
- موقع RETFound الأصلي: http://127.0.0.1:8002

كل منهما يتصل عبر خادمه الوسيط بالرابط الخارجي. المتصفح لا يطلب مفتاحًا،

ملفات تصميم الواجهتين تُحمّل محليًا؛ بيانات النموذج والتحليل تمر عبر
الـAPI الخارجي. لذلك فتح صفحة الموقع لا ينتظر تنزيل HTML عبر Cloudflare.
ولا يستلم مفتاح OpenRouter أو RETFound. النموذج يُحمّل مرة واحدة على 8000.
إغلاق نافذة التشغيل أو Ctrl+C يوقف جميع العمليات التي بدأها هذا التشغيل.
لا تغلق عمليات قديمة إلا من نوافذها؛ وجود منفذ محجوز يمنع بدء نسخة ثانية.
`--api-only` يشغّل الخادم والنفق دون التطبيقين.

## جهاز زميلك

انسخ مجلد eye-ai-demo دون .runtime أو ملفات الأسرار القديمة، وأرسل له
نسخة connection.json الحالية بشكل خاص ليضعها في جذر eye-ai-demo.
لا يحتاج النموذج أو ملفات الأوزان أو OpenRouter، لكن يحتاج Python وحزم
backend/requirements.txt في بيئته. لا تشارك بيئة Conda المنسوخة من جهازك.

من مجلد eye-ai-demo على جهازه، باستعمال Python مجهز بالحزم:

```text
python run_demo.py --connection-file connection.json
```

يفتح http://127.0.0.1:8001 على جهازه هو، ويُرسل خادمه الصور إلى الـAPI
الخارجي على جهازك. هذا رابط محلي لواجهته وليس رابطًا عامًا يمكن إرساله
لأجهزة أخرى. عند إعادة تشغيل النفق، أرسل ملف الاتصال الجديد وأعد تشغيل
خادم الديمو لديه. حفظ الملف على جهازك لا يحدث نسخته عن بعد تلقائيًا.

يمكن تشغيل الموقع الأصلي وحده من جهازك:

```powershell
& "$env:USERPROFILE\.conda\envs\ml-homework\python.exe" -B "C:/Users/jadgh/Desktop/Dr 4/Dr/RETFound/scripts/serve_site.py"
```

ثم RETFound وفق المسار الحالي. لا توجد إعادة محاولة تلقائية لطلب التنبؤ.
